## 三、第二轮：MP3 三项增强（SRT 逐句 / 实体键切段 / 离线缓存）

### 第三轮（最新包）：播放条重排 + AB 复读——用户重新定义的方案

用户明确不要"时间轴上一堆书签刻度"，并把播放条改成：

- **主排**：`[上一句] [播放] [下一句]`（同 TTS 排布；默认逐句切换，SRT cues 驱动，
  不依赖循环/自动暂停是否激活）。±10s 按钮移除。
- **副排**：循环、自动暂停、**单个 AB 复读键**（原书签三键 `< 加删 >` 收敛）、
  倍速、TTS 切换。
- **AB 键三态**（会话级）：熄灭 → 点按标 A（图标 repeat_one）→ 再点标 B 并立即
  回 A 开始 **A↔B 循环**（图标 repeat_on 点亮、时间轴画 A/B 三角标记与高亮段）→
  再点取消。B 标到 A 之前视为无效退回熄灭。
- **概念分离**：`segmentBoundaries`（句子分段，SRT 派生，驱动循环/自动暂停/切句，
  **不画时间轴**）与 `bookmarkDurations`（用户真书签，画刻度）彻底分开；
  书签按钮 UI 移除 → addBookmark/removeBookmark 无调用者 → 服务端书签列零风险。
- 实体键逻辑不变（循环/自动暂停激活 → 切句，否则翻页）。

**验证实录（v11 装机实测，全部通过 ✅）**：
- 时间轴无伪刻度；主排 `< 播放 >` 切句生效（单按/连按 3 次累计前进 52 秒，高亮跟随）。
- AB 三态：标 A（图标变 repeat_one）→ 播放中标 B（图标 repeat_on、播放头回 A）→
  logcat 连续 4 次 `AB loop reached B(≈8s), back to A(0)`，位置在 A↔B 间循环 →
  再点取消，播放继续不再回绕。
- 循环键图标改为 `Icons.loop`，与 AB 的 repeat 系区分。

### 第四轮：循环模式下"单击切句被回绕吃掉"的竞态修复（v14 ✅）

用户报告：MP3 开循环后**双击**实体键才切下一句，单击像是在重播当前句。
实证（logcat）：`>` 切到下一句的 seek 之后，**seek 之前在途的旧位置事件迟到落地**，
把 `state.position` 拉回旧句；跨越检测据此误判"越过句尾"，循环模式立即把播放头
拽回旧句句首重播 —— 单击的效果被吃掉，第二次按键才真正停在新句上。

修复：`seek()`（切句/拖进度条/AB 内部的显式 seek 共用）设置
`_boundaryHandledAt`，**600ms 内不做跨越判定**，吞掉 seek 回声。与既有的
"自动暂停 seek 回句首不收暂停态事件"（paused 守卫）互补。

装机实测（v14 = `lute-mp3-fixseek_202609290318.apk`，sha1 `ab3e2e84…`，当前装机）：
循环激活下**单击** PAGE_DOWN 即切到下一句（13.149→19.003），循环稳定绕新句
（每 ~6s 回绕一次），不再弹回旧句。✅

顺带记录：SRT 书的第一句往往极短（"作詞：…"元数据行，~1s），循环激活时
它每秒回绕一次是正常现象（每条 cue 就是一句）。另：冷启动后第一次点播放
偶尔不起播、第二次才起（起播兜底路径的既有怪癖，非本轮引入，待观察）。

用户需求：① MP3 播放器也要实体键上下切换（和 TTS 切句同体验，对齐 web Song）；
② MP3 书离线可听；③ 自动暂停按 **SRT 每一句**停（"srt 每一个句子就是一句"）。

### 第二轮查明并修掉的 4 个真 bug（全部在设备上实证过）

| # | Bug | 修复 |
|---|-----|------|
| 1 | **MP3 分段"滑动窗口"**：`_handlePositionChanged` 用"当前位置归属哪段"算段尾，位置一越过书签归属跟着滑走，`position >= 段尾` 永不成立 → MP3 循环/自动暂停**从来不会触发**（全曲除最后一段）。v4 装机实证：JIGSAW 一路播完不停。 | 改为**越界检测**：比较上一个位置事件与本次事件，跨越某书签 = 句子播完。`audio_player_provider.dart` `_handlePositionChanged`（含 600ms `_boundaryHandledAt` 防连环触发）。 |
| 2 | **SRT 没进播放器**：服务端 `youtube_player.html` 只发 `LUTE_YT_DATA.cues`（`[{start,end,text}]`），**不发 bookmarks**；app 只认 bookmarks → SRT 书永远没有分段。 | `reader_screen.dart` `_resolveAudioBookmarks`：服务端书签优先，缺位时用每条 cue 的 `start` 派生分段。JIGSAW 实测 62 cues → 62 段。 |
| 3 | **派生分段被 widget 清空**：`AudioPlayerWidget` 的 postFrame 重载用页面原始 props（书签=null）调 `loadAudio`，把 `_loadAudioIfNeeded` 派生的 62 条覆盖成 0。仪表化构建实证：load 时 62 条，按键时 `bms=0`。 | 派生逻辑提成 `_resolveAudioBookmarks`，`_loadAudioIfNeeded` 与 widget 构造**共用**；widget 新增 `bookmarksFromCues` 参数透传。 |
| 4 | **暂停态迟到位置事件**：自动暂停 seek 回句首 / 切到下一句的 seek 之后，在途的旧位置事件把 `state.position` 盖回旧值（显示回跳、切句"看起来没动"）。 | `_handlePositionChanged` 开头：**非 playing 状态一律不收位置事件**（显示由 seek() 的显式写入负责）。 |

另两个相关修复（第一轮遗留的联动）：
- **playerMode 门控**：纯文本书 TTS 条常显但 playerMode 停在 mp3，实体键门控改用
  `_showTtsPlayer()` 口径（"TTS 条是不是当前显示的播放条"）。

### MP3 离线缓存（需求②）

`_ensureLocalAudioFile`（audio_player_provider.dart）本来就会把音频流式下载到
`getApplicationCacheDirectory()/audiobooks/audiobook_<bookId>_<urlhash>.audio`
并按大小复用。真正的离线 bug：**Range 探测失败（离线）后无条件走下载**，缓存被无视。
修复：
- 探测失败且缓存文件存在 → 直接用缓存（离线可听）；
- `ServerStatusManager.isReachable == false` 时完全跳过探测（不再白等 15s 超时）；
- 缓存缺失时照旧下载（离线时照旧报错）。
注意：仅 auth 路径（`SessionManager.authHeaders()` 非空）走缓存文件；无 auth 的
书仍是 setSourceUrl 直连流播（用户的服务器走 Song 登录，覆盖此场景）。

### 防数据污染（重要，勿回退）

SRT 派生分段是字幕的投影，**绝不写回** `BkAudioBookmarks`：
- `loadAudio(..., bookmarksFromCues: true)` → `_bookmarksFromCues=true` →
  `_bookmarksAuthoritative=false`；
- `_savePosition` 里 `userEdited: includeBookmarks && !_bookmarksFromCues`
  → 书签按钮的编辑也不会把派生值 POST 回服务端；
- 服务端书签列（老式 `input#book_audio_bookmarks`）书依旧原样工作。

## 五、设备行为备忘（Leaf5C，防重复踩坑）

- **BOOX 系统层吞音量键码**：注入/实体 `KEYCODE_VOLUME_*` 到不了 app；PAGE_UP/DOWN
  键码能到。app 两种都接（`hardware_key_navigator.dart`）。若用户实体键不响应，
  让他检查文石「应用优化→按键设置」是否映射成 PageUp/PageDown。
- **`input keyevent` ≠ 桌面点击路径**：旧包复现"新实例"用 shell 不稳定，但
  singleTask 在任何路径下都保证单实例。
- **截图是物理像素**（1264×1680），`input tap` 一一对应；PIL 量坐标别凭预览估。
- JIGSAW 播放条按钮物理坐标：自动暂停 (640,438)、循环 (566,438)、书签+/- (411,438)、
  下一书签 `>` (488,438)、播放/暂停 (632,355)、时间轴最左 (80,270)、−10s (531,349)。
- 夜の色彩（bookId 非 273，text 书）只有 1 页：`_canSwipePages` 对 pageCount<=1
  返回 false，实体键"翻页"在这本书上无事可做，别误判成按键坏了。
