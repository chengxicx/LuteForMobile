### ⚠️ Build invocation (this tripped us twice)
Do **NOT** run `systemd-run … bash /opt/build_apk.sh` directly — the unit exits instantly and `--wait` does not actually wait, so you get a "success" with no APK. Use the redirect-to-log pattern and poll:

```bash
# 1. re-apply memory-constrained gradle.properties (the build script may overwrite it)
ssh … root@172.236.226.132 'cat > /opt/lute_mobile_src/android/gradle.properties <<EOF
org.gradle.jvmargs=-Xmx1280m -XX:MaxMetaspaceSize=512m -XX:ReservedCodeCacheSize=128m
org.gradle.parallel=false
org.gradle.workers.max=1
org.gradle.daemon=false
org.gradle.caching=false
android.useAndroidX=true
android.enableJetifier=true
android.builtInKotlin=false
android.newDsl=false
EOF
rm -f /tmp/buildN.log
systemd-run --collect --unit=fbuildN -p MemoryMax=2400M -p MemorySwapMax=3G --setenv=HOME=/root \
  bash -c "bash /opt/build_apk.sh > /tmp/buildN.log 2>&1; echo EXIT=\$? >> /tmp/buildN.log"'

# 2. poll (the build takes ~5-7 min):
ssh … 'systemctl is-active fbuildN.service; grep "EXIT=" /tmp/buildN.log | tail -1'
```

## 4. Task ③ — Navigation rework  ✅ code / ✅ built / 🔴 NOT visually verified

**Design (this is the spec the next AI must confirm on device):**
- Shared constant `kNavDestinations` (in `app_drawer.dart`) lists all 7 destinations in one place so bar / drawer / rail can't drift: `reader, books, grammar, terms, stats, help, settings`.
- **Narrow (< 600 px, phones):** bottom `NavigationBar` with the **5 main** sections only (`reader, books, grammar, terms, stats`). The `AppBar` hamburger opens `AppDrawer`, which offers **only `help` + `settings`** (no duplication) plus a contextual settings panel. Bottom bar is hidden on Settings/Help (since those are drawer-only).
- **Wide (≥ 600 px):** no drawer, no bottom bar. A **persistent `NavigationRail`** on the left carries **all 7** destinations; it expands to icon+label at **≥ 900 px** (`_extendedRailMinWidth`). Breakpoints are `app.dart:196` (`_wideLayoutMinWidth = 600`) and `app.dart:199` (`_extendedRailMinWidth = 900`).
- `AppBarLeading` status icons (server-unreachable warning / session-expired): when there's **no drawer** (wide), they navigate **directly to Settings** (`navigationProvider.navigateToScreen('settings')`); when a drawer exists, they open it. The hamburger (`Icons.menu`) is **still present** — so Settings/Help remains reachable on phones.

**Files:**
- `lib/app.dart` *(modified)* — removed the old in-drawer rail; `_navBarRoutes` = 5 main; `_drawerRoutes` getter returns `['help','settings']` when the bar is visible else all 7; `_stackRoutes` maps `settings`→5; `build()` shows `AppDrawer` (narrow) or `NavigationRail` + body (wide); `_buildRail()` builds the persistent rail.
- `lib/shared/widgets/app_drawer.dart` *(rewritten)* — width 320, **no rail**; top shows contextual panel (`ReaderDrawerSettings` / `BooksDrawerSettings` / `null`), bottom shows `ActionChip`s for the drawer routes + version string.
- `lib/shared/widgets/app_bar_leading.dart` *(modified)* — status icons route to Settings when no drawer; otherwise open the drawer.

**Verification done:** `flutter analyze` 0 error; APK built (build4, `EXIT=0`, 27 MB) and installed once via `adb install -r`.
